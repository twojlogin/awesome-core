Awesome Core — lokalny katalog narzędzi z awesome list

Jeden silnik (SQLite + FTS5), cztery wejścia: CLI, TUI, Web i MCP dla lokalnych agentów. Po pobraniu list zero sieci — wszystko działa lokalnie.

Nic nie działa w tle

Żadnych cronów, daemonów ani ukrytych procesów. Odświeżanie uruchamiasz ręcznie — jednym poleceniem albo klikając przycisk na stronie /refresh. Każdy krok wypisuje log i czeka na zakończenie, więc zawsze widzisz, co się stało.

Pierwsze uruchomienie

./awesome start          # pobierz listy → zbuduj bazę → metadane list
./awesome start --full   # ...plus metadane narzędzi (dłuższe, ~30–60 min)
./awesome status         # co jest w bazie i co warto odświeżyć
./awesome doctor         # coś nie działa? tu jest odpowiedź

start nie odpytuje GitHuba o repozytoria samych narzędzi — ranking działa od razu, ale „★" przy narzędziu to na razie szacunek z listy. Jedna komenda to naprawia: ./awesome enrich (30–60 min, Ctrl+C jest bezpieczny, dokończenie jedzie od miejsca przerwania), potem ./awesome build.

Na Windows: awesome.cmd start — działa w PowerShellu i po podwójnym kliknięciu, bez basha.

Odświeżanie później: ./awesome refresh (kolejność i czasy wypisuje na ekranie). Pojedyncze kroki: ./awesome download · ./awesome build · ./awesome backfill · ./awesome enrich. Plan bez wykonywania: ./awesome refresh --dry-run.

Wyszukiwanie po ludzku

./awesome search "port scanner"
./awesome search osint --domain security --min-consensus 3
./awesome search "active directory" --os windows

Filtry: --lang --os --domain --list --min-stars --min-consensus --sort (score, stars, consensus, underrated, gem, name) --alive.

Filtry łączy AND, więc kumulują się. --lang Python --os windows przy „port scanner" zostawia 5 wyników, a z trzecim filtrem często jeden przypadkowy. Program mówi wtedy wprost, który filtr odpuścić i ile wtedy wychodzi.

Fasetyki

./awesome langs          # języki narzędzi
./awesome platforms      # windows, WSL, Linux, macOS, Docker, CLI…
./awesome domains        # osint, security, network, devops, reverse-engineering…
./awesome lists          # najlepsze listy wg jakości
./awesome underrated     # dobre narzędzia z małych list
./awesome gems           # ukryte perełki

Rzadziej używane

./awesome clones          # kopie i forki list (próg 80%)
./awesome untrusted       # skan opisów pod kątem prompt injection
./awesome consensus       # narzędzia z największą zgodą kuratorów
./awesome top 10          # top list wg gwiazdek
./awesome repos osint     # szukaj list/repozytoriów
./awesome watch add vinta/awesome-python   # śledzone repozytoria list
./awesome install nmap    # git clone narzędzia
./awesome demo            # co program potrafi, na żywo

watch i shortlist to dwie różne listy: watch śledzi repozytoria list (co doszło nowego), shortlist zbiera narzędzia i generuje Markdown.

Skąd ranking

Score to nie gwiazdki listy, tylko: zgoda niezależnych kuratorów (czyli w ilu różnych listach narzędzie występuje), jakość listy, własne gwiazdki narzędzia z GitHub API, żywy link, opis i kompletność metadanych.

./awesome why nmap                 # rozkład punktów
./awesome mentions nmap            # wszystkie listy, w których jest
./awesome info nmap                # szczegóły + komenda instalacji
./awesome list vinta/awesome-python # narzędzia z jednej listy

Twoja własna lista

Znalazłeś coś, co działa? Włóż to od razu na swoją listę. Na końcu wygeneruj Markdown do wklejenia we własnym README.

./awesome shortlist add nmap --note "do skanowania"
./awesome shortlist
./awesome shortlist emit --out moja-lista.md

W przeglądarce: przycisk ☆ Do mojej listy na stronie narzędzia, potem link Moja lista → Markdown do wklejenia. W TUI: klawisz k.

Podłącz lokalnego agenta AI (MCP)

Katalog jako źródło narzędzi dla agenta — lokalnie, bez kluczy API i bez wysyłania czegokolwiek do sieci. Ranking oparty o zgodę niezależnych kuratorów, nie o to, co najczęściej wypisane w jednym README.

./awesome mcp --demo    # podgląd wymiany JSON-RPC
./awesome mcp           # serwer dla agenta (stdio)

W claude_desktop_config.json (lub analogicznie w Cursorze):

{
  "mcpServers": {
    "awesome-core": {
      "command": "/pełna/ścieżka/do/awesome-core2/awesome",
      "args": ["mcp"]
    }
  }
}

Narzędzia serwera: search_tools, find_undiscovered_tools, explain_tool, lists_with_tool, catalog_facets. Serwer czyta bazę i nic nie zapisuje.

TUI

./awesome tui

/ szukaj · l język · o platforma · d domena · s sort · a wyczyść filtry · g perełki · u niedoceniane · Enter szczegóły · k do mojej listy · i instalacja · ? pomoc · q wyjście

Dane i eksport

./awesome stats             # co jest w bazie
./awesome validate --limit 100   # sprawdź martwe linki
./awesome export json --out tools.json   # do pliku, który podasz
./awesome export csv  --out tools.csv
./awesome web              # Flask UI (port wypisuje na ekranie)

Flaska nie musisz instalować ręcznie — przy pierwszym ./awesome web program tworzy venv i instaluje requirements.txt, wypisując każdy krok.

Limity, o których trzeba wiedzieć

  • Wyszukiwarka GitHuba zwraca maks. 1000 wyników na zapytanie — dlatego ./awesome download używa kilku zapytań i skaluje wyniki.
  • Prawdziwy język narzędzia znamy tylko tam, gdzie doszedł ./awesome enrich; bez tego lang bywa ?.
  • Linki poza GitHubem sprawdzamy tylko jawnie: ./awesome validate --non-github --limit 500.

Bezpieczeństwo

Sygnały przy repozytoriach (archiwalne, dawno nieaktualizowane) to wskazówki do sprawdzenia, a nie etykieta bezpieczeństwa. Zawsze przejrzyj kod i release'y przed instalacją. Instalacja z weba to wyłącznie git clone do katalogu narzędzi — nie jest to terminal.

README jest jednym źródłem prawdy: opisuje też skąd biorą się listy, dlaczego nic z cudzego repozytorium nie jest wykonywane i jedyne miejsce, gdzie opis z obcej listy trafia do kontekstu modelu (MCP).
